01 · El veredicto

No te falta un sitio. Te sobran «ahoras».

FOCUS.md debería ser un estado de una pantalla. Es un diario de 3.924 líneas con 21 secciones «Ahora», muchas ya cerradas. Por eso el proyecto sigue en tu cabeza: el fichero que mentalOS lee ya no se puede escanear.

DECISIONS.md sí es la herramienta correcta —ley, no tablero—. El error es usarlo para saber qué toca hoy. Las specs en docs/superpowers/ y los HTML de diseño están bien donde están. Claude Tasks y Hermes Kanban no son la fuente de verdad: se pudren en cuanto dejas de mirarlos.

Lo que no vamos a hacer

No montar Linear, no un quinto markdown, no un kanban paralelo. Tres ficheros con oficio distinto. Yo los mantengo. Tú decides lo subjetivo (qué hilo, visto bueno de UI). Yo corto, brief, lanzo, verifico, actualizo.

03 · El ciclo de una sesión conmigo

01

Yo llego y leo dos cosas

Este tablero + FOCUS corto. No las 7.000 líneas. Si FOCUS sigue gordo, lo primero que hago es extraer el estado, no releer el diario.

02

Te propongo UN corte

«Hoy es X, no Y.» Si hay dos hilos que no se pisan (backend FIT + visto bueno de UI), como mucho dos. Nunca un backlog entero en una sesión de Grok o Claude.

03

Tú decides solo lo subjetivo

Qué hilo, si se shipea Swift, copy, layout. Lo objetivo (el modelo está incompleto, falta un campo, el test no cubre el caso) lo cierro yo sin preguntarte.

04

Yo fabrico el brief y lanzo

Grok Build por defecto (backend, dominio, tests, importadores). Claude Code solo UI/UX gorda. Bugs de 1–3 líneas: yo, sin agente. El brief siempre lleva el «NO hacer» de DECISIONS de esa pieza.

05

Verifico, actualizo, commiteo

Diff + tests/typecheck. Actualizo tablero + FOCUS. Si hubo decisión o descarte, una entrada en DECISIONS. Commit pequeño, rutas explícitas. Nada de git add -A ni stash.

Grok Build

Default. grok -p con --always-approve y tope de turns. Rápido. Backend, motores, migraciones, FIT, tests.

Claude Code

Solo cuando la pieza es UI/UX y Grok no da el nivel. Max OAuth, sin API key, sesiones cortas.

Hermes directo

Constantes, un if, un redirect, un texto. Más barato que abrir un agente que se lee media app.

Nadie

Si falta tu ZIP, tu visto bueno o una decisión de producto: se queda en «espera Alex». No se inventa para no parar.

04 · Cómo se fabrica un brief (para no iterar lo mismo)

El fallo caro no es el modelo. Es relanzar «sigue con Carrera» sobre un contexto sucio, sin el NO HACER, y que el agente reconstruya el CTA de tests que ya tiramos.

Plantilla fija. Yo la relleno. Tú no escribes prompts.

Objetivo: …
Criterios de done: (3–6, observables)
Contexto de producto: 4–8 líneas. Por qué existe esta pieza.
Ley ya firmada (NO reabrir):
  - citas literales de DECISIONS / mapa
Pistas (hipótesis, no órdenes):
  - archivos / commits. Si el código dice otra cosa, manda el código.
Fuera de alcance: …
Verificar: comandos concretos (test / typecheck / twin:desfase)
Al terminar: actualizar tablero + FOCUS; DECISIONS solo si hay decisión nueva.
No commitear secretos. No git add -A. No stash.

Anti-iteración: si una sesión falla, la lección se escribe en la fila del tablero («ya se intentó X, no repetir»). El siguiente brief la lleva arriba. No se relanza el mismo prompt.

07 · Dónde puede fallar

  • FOCUS vuelve a crecer. Regla: si una sección «Ahora» tiene más de 12 líneas, sobra. El detalle va al tablero o a la spec.
  • Otra sesión de Claude Code reescribe FOCUS como diario. Lo evito yo: el brief dirá «FOCUS solo se toca en el bloque Ahora, máximo 80 líneas».
  • El tablero se queda en 13-ago. Si un commit de trabajo no actualiza este HTML, el commit está incompleto. Igual que FOCUS.
  • Dos hilos en la misma rama. Worktrees o una rama por hilo. Hoy PM5 y Carrera no deberían compartir checkout si los dos se mueven.
  • Brief demasiado cerrado. Pistas de archivos son hipótesis. Ya nos ha pasado: Hermes ordena una línea y el agente obedece un diagnóstico falso.

Lo que rompí contra la realidad (antes de proponerte esto)

  • FOCUS 3.924 líneas vs la regla escrita en CLAUDE.md: «Corto — es un estado, no un diario».
  • 21 «Ahora» simultáneos + la rama git es PM5, que FOCUS ya no tiene arriba. El mapa mental y git no coinciden.
  • DECISIONS sí se escribe (hoy +51 líneas sin commitear de otra sesión). El problema no es que falte ley, es que no hay índice.
  • mentalOS solo ve disco + git. Si no está commiteado y en FOCUS corto, para ti no existe.
