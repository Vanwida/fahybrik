La forma más limpia de hacer V2 primario es quitar el prefijo /v2 moviendo (v2)/v2/* al sitio de (app)/* y reapuntar el login a /hoy. 1 · Inventario de rutas (V1 vs V2)

Los route groups entre paréntesis ((app), (v2), (marketing)…) no añaden segmento de URL. Por eso:

  • (app)/hoy → URL /es/hoy  (V1, lo que se sirve hoy)
  • (v2)/v2/hoy → URL /es/v2/hoy  (V2, el /v2 es un segmento real dentro del grupo)

El layout (v2)/layout.tsx envuelve TODO lo de (v2)/v2/* con V2Shell + v2-theme.css (tema scoped al wrapper .v2-root, no toca el <html>; por eso V1 y V2 conviven sin pisarse).

2 · Mecánica de routing y el switch v1↔v2

Cómo está cableado (v2)

  • app/[locale]/(v2)/layout.tsx — mismo gate de auth que V1 (getCoachSession() → redirect('/sign-in')), lee unread de chat, monta <V2ThemeScript/> + <V2Shell>. Importa ./v2-theme.css.
  • (v2)/v2-theme.css — tokens del tema V2, scoped a .v2-root.
  • components/v2/V2Shell.tsx — chrome cliente: V2ThemeProvider + V2Sidebar + barra superior con VersionSwitch, ThemeToggle y nombre del coach.
  • components/v2/nav.ts — IA del sidebar V2 (V2_NAV_ITEMS, hrefs /v2/...). Totalmente independiente de la nav V1 (el "import" aparente de lib/dashboard/nav.ts es solo un comentario, no una dependencia real).

Cómo está cableado (app) (V1)

  • (app)/layout.tsx — getCoachSession() + countCoachInboxItems() → <AppShell> (de components/dashboard/layout/AppShell).
  • Nav V1: lib/dashboard/nav.ts + components/dashboard/layout/CoachSidebar.tsx / CoachMobileNav.tsx.
El switch "v1 / v2" de las capturas = components/v2/VersionSwitch.tsx Es un toggle dentro de la barra superior de V2. La pastilla v2 está activa (no es link, es el estado actual); la pastilla v1 es un <Link> que mapea la pantalla V2 actual a su gemela V1 (V2_TO_V1_ROUTE: hoy→/hoy, atletas→/atletas, biblioteca→/programar…) y cae a /hoy si no hay gemela. Solo existe en V2 (V1 no tiene botón para ir a V2 — a V2 se llega tecleando /v2/...). Al consolidar, este componente se borra (junto con su uso en V2Shell).

3 · Qué sirve /es/hoy HOY

Hoy sirve V1. Traza: el login del coach (magic-link) está en app/auth/verify/route.ts y en su línea 46 hace NextResponse.redirect(new URL('/hoy', appUrl)) → next-intl prefija el locale → /es/hoy → resuelve a (app)/hoy/page.tsx (V1). Los compañeros de Pablo que entran online aterrizan en V1. A V2 solo se llega tecleando /v2/.... Por eso, consolidar no es opcional para que el redirect de login lleve a la versión buena: o se mueve V2 a /hoy, o se cambia el destino del redirect a /v2/hoy.

Retirar el dashboard V1 web NO afecta a la app iOS del atleta. iOS consume app/api/athlete/* (+ api/auth, api/onboarding, api/chat, api/devices, etc.), no las páginas (app)/(v2). Lo único a respetar:
  • NO tocar los redirects /privacy→/es/privacy y /terms→/es/terms de next.config.ts (iOS hardcodea las URLs bare para la App Store).
  • NO mover/borrar lib/dashboard/v2/zone-profile.ts (lo usa api/athlete/zones) ni nada de lib/dashboard/v2 o lib/dashboard/coach que la API athlete pueda tocar.
  • Las páginas legales viven en (public) — route group aparte, intacto.
Otro agente está editando web/lib/athlete/assignment-detail.ts y web/app/api/athlete/plan/week/route.ts — ninguno de esos archivos forma parte de este plan; no se tocan.
