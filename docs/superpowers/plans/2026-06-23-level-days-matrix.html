Level × Days Matrix System

Plan de implementación · FAHYBRIK · 23 junio 2026

Objetivo: Sistema de dos dimensiones (nivel × días/semana) que auto-sugiere el nivel de un atleta desde sus benchmarks de onboarding, deja a Pablo etiquetar cada bloque con (nivel, días), muestra una matriz visual de cobertura en la biblioteca, y envía una propuesta al coach en /hoy cuando llega un atleta nuevo.

Arquitectura: (1) Fundación de BD — tabla athlete_levels por coach, tags de nivel+días en blocks, campos de nivel en athletes. (2) Algoritmo server-side — lee athlete_benchmarks y sugiere nivel 1-5. (3) Dashboard V2 — biblioteca con vista matriz, editor de bloque con pickers, card "nivel sugerido" en /hoy, y nivel real en el roster.

Stack: PostgreSQL (Neon) · Next.js 15 App Router · TypeScript · Zod · shadcn/ui · Tailwind CSS v3

Restricciones globales

  • Próxima migración: 0057 → directorio infra/migrations/
  • Todo el código web bajo web/
  • Agnóstico a la metodología: cero referencias a ATR (ACC/TRANS/REAL) en código nuevo
  • blocks.id es bigserial — las FKs usan bigint, no uuid
  • athletes.training_days_per_week ya existe (int, derivado de availability_json)
  • Slugs de benchmarks en athlete_benchmarks: hyrox_open, hyrox_pro, run_5k, row_2k, back_squat
  • Snake_case en todas las columnas de BD y respuestas de API
  • Los niveles son por coach (coach_id FK en athlete_levels)
  • Seed por defecto N1-N5 para todos los coaches existentes al aplicar la migración
  • Los umbrales del algoritmo son sex-aware (leen athletes.sex)
  • Fuera de alcance: baterías de tests por nivel, re-nivelado automático, tiers de precio

Paso 1
Escribir infra/migrations/0057_athlete_levels.sql
-- Catálogo de niveles por coach
create table athlete_levels (
  id          bigserial primary key,
  coach_id    bigint not null references coaches(id) on delete cascade,
  name        text not null,        -- 'N1', 'N2', etc.
  label       text not null,        -- 'Iniciación', 'Desarrollo', etc.
  description text,
  sort_order  smallint not null default 0,
  created_at  timestamptz not null default now(),
  constraint athlete_levels_coach_name_uq unique (coach_id, name)
);
create index athlete_levels_coach_idx on athlete_levels (coach_id, sort_order);

-- Tags de nivel + días en bloques
alter table blocks
  add column if not exists min_level_id  bigint references athlete_levels(id) on delete set null,
  add column if not exists max_level_id  bigint references athlete_levels(id) on delete set null,
  add column if not exists days_per_week smallint,
  add constraint blocks_days_per_week_chk
    check (days_per_week is null or days_per_week between 1 and 7);

-- Nivel asignado en atletas
alter table athletes
  add column if not exists level_id           bigint references athlete_levels(id) on delete set null,
  add column if not exists suggested_level_id bigint references athlete_levels(id) on delete set null,
  add column if not exists level_source       text check (level_source in ('algorithm','coach','self_reported')),
  add column if not exists level_confidence   text check (level_confidence in ('low','medium','high'));

-- Seed N1-N5 para todos los coaches existentes
insert into athlete_levels (coach_id, name, label, description, sort_order)
select c.id, lvl.name, lvl.label, lvl.description, lvl.sort_order
from coaches c
cross join (values
  ('N1','Iniciación',  'Primera experiencia estructurada. Sin carreras o >90min.',1),
  ('N2','Desarrollo',  'Base aeróbica, 0-1 carreras. 75-90min.',2),
  ('N3','Rendimiento', '1-3 carreras, entiende zonas. 65-75min.',3),
  ('N4','Competición', 'Open competitivo, múltiples carreras. 55-65min.',4),
  ('N5','Elite',       'Pro o sub-elite. <55min (H) / <65min (M).',5)
) as lvl(name,label,description,sort_order)
on conflict (coach_id, name) do nothing;

6
Auto-propuesta en /hoy cuando llega atleta nuevo

Flujo completo del nuevo atleta:

  1. Atleta completa el onboarding en iOS.
  2. Coach aprueba el intake en el dashboard.
  3. Al aprobar → se ejecuta computeAndStoreLevelSuggestion(athleteId, coachId).
  4. El algoritmo lee benchmarks + perfil → guarda suggested_level_id + level_confidence en el atleta.
  5. En /hoy, aparece una card nueva tipo nivel_sugerido: "Ana · Nivel sugerido: N2 · Confianza: media" con botones [Aceptar nivel] y [Ver atleta].
  6. Coach hace click en Aceptar → level_id se fija, level_source = 'coach', la card desaparece.
